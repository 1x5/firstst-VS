# 🔍 Анализ проблем со сбросом пароля

## Проблемы

### 1. 404 ошибка для `/auth/reset-password`
**Симптом:** `Failed to load resource: the server responded with a status of 404`

**Причина:**
- GitHub Pages пытается найти физический файл по пути `/auth/reset-password`
- После `navigate('/auth/reset-password')` может происходить перезагрузка страницы
- React Router не успевает обработать маршрут до перезагрузки

**Решение:**
- Не использовать `navigate` сразу после установки сессии
- Использовать `window.history.replaceState` для очистки hash без перезагрузки
- Убедиться, что роутинг обрабатывается на клиенте

### 2. 400 Bad Request при обновлении пароля
**Симптом:** `POST https://bjtdndmywxtfhzlfwinf.supabase.co/auth/v1/token?grant_type=password 400`

**Причина:**
- Recovery сессия не позволяет использовать `grant_type=password`
- Для recovery сессии нужно использовать `updateUser` с паролем, а не `signIn`
- Возможно, recovery токен истек или недействителен
- Сессия не установлена правильно после `setSession`

**Решение:**
- Проверить, что сессия установлена перед `updateUser`
- Убедиться, что используется правильный метод (`updateUser`, а не `signIn`)
- Добавить проверку типа сессии (recovery vs regular)

### 3. Уведомления не показываются
**Симптом:** Экран успеха не появляется после обновления пароля

**Причина:**
- `passwordUpdated` устанавливается в `true`, но компонент перерендеривается
- `mode` может сброситься до `'login'` после навигации
- Состояние теряется при перезагрузке страницы

**Решение:**
- Сохранять состояние в sessionStorage
- Проверять состояние при монтировании компонента
- Не сбрасывать `mode` после успешного обновления
