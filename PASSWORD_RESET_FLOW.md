# 🔄 Процесс сброса пароля - Пошаговый анализ

## Идеальный flow (что должно происходить)

### Этап 1: Запрос сброса пароля
1. Пользователь нажимает "Забыли пароль?"
2. Вводит email
3. Нажимает "Отправить ссылку"
4. **Ожидаемый результат:** Письмо отправлено, показывается сообщение об успехе

### Этап 2: Получение письма
5. Пользователь получает письмо от Supabase
6. В письме есть ссылка вида: `https://uchet1.ru/auth/reset-password#access_token=...&type=recovery&...`
7. **Ожидаемый результат:** Ссылка корректная, содержит все необходимые токены

### Этап 3: Переход по ссылке
8. Пользователь кликает по ссылке в письме
9. Браузер открывает: `https://uchet1.ru/auth/reset-password#access_token=...&type=recovery&...`
10. **Ожидаемый результат:** 
    - Страница загружается
    - Hash с токенами обрабатывается
    - Сессия устанавливается через `setSession`
    - Показывается форма для ввода нового пароля

### Этап 4: Ввод нового пароля
11. Пользователь видит форму с полями:
    - Email (заполнен автоматически или скрыт)
    - Новый пароль
    - Подтверждение пароля
12. Вводит новый пароль (минимум 8 символов, буквы и цифры)
13. Вводит подтверждение пароля
14. Нажимает "Обновить пароль"
15. **Ожидаемый результат:**
    - Пароль валидируется
    - Вызывается `updateUser({ password: newPassword })`
    - Пароль обновляется в Supabase
    - Показывается экран успеха

### Этап 5: Успешное обновление
16. Пользователь видит сообщение "Пароль успешно изменён!"
17. Нажимает "Войти с новым паролем"
18. **Ожидаемый результат:**
    - Выход из recovery сессии
    - Перенаправление на страницу входа
    - Пользователь может войти с новым паролем

## Текущие проблемы

### Проблема 1: 404 ошибка при переходе по ссылке
- **Симптом:** `GET https://uchet1.ru/auth/reset-password 404 (Not Found)`
- **Причина:** GitHub Pages не знает о маршруте `/auth/reset-password`
- **Решение:** Нужно правильно обработать через 404.html

### Проблема 2: Hash не обрабатывается
- **Симптом:** Hash с токенами теряется или не обрабатывается
- **Причина:** Возможно, hash теряется при редиректе через 404.html
- **Решение:** Нужно сохранять hash в sessionStorage и восстанавливать

### Проблема 3: Смена пароля не работает
- **Симптом:** После ввода нового пароля ничего не происходит или ошибка
- **Причина:** Возможно, сессия не установлена или токен истек
- **Решение:** Нужно проверить наличие сессии перед обновлением пароля
