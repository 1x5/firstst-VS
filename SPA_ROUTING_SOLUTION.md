# 🔧 Оптимальное решение для SPA routing на GitHub Pages

## ✅ Текущее решение (улучшенное)

Используется **Vite плагин**, который автоматически создаёт `404.html` из `index.html` при каждой сборке.

---

## 📊 Сравнение подходов

### ❌ Вариант 1: HashRouter
```tsx
// Плохо для UX
<HashRouter>
  <Route path="/#/income" />  // URL с # выглядит некрасиво
</HashRouter>
```
**Минусы:**
- URL выглядит некрасиво (`/income` → `/#/income`)
- Плохо для SEO
- Не соответствует современным стандартам

---

### ⚠️ Вариант 2: Ручное копирование в GitHub Actions
```yaml
# .github/workflows/deploy.yml
- name: Copy index.html to 404.html
  run: cp dist/index.html dist/404.html
```
**Минусы:**
- Нужно помнить об этом шаге
- Дублирование логики
- Не работает локально при `pnpm build`

---

### ✅ Вариант 3: Vite плагин (текущее решение)
```ts
// vite-plugin-github-pages-404.ts
export function githubPages404(): Plugin {
  // Автоматически создаёт 404.html при каждой сборке
}
```

**Плюсы:**
- ✅ Автоматически работает при каждой сборке
- ✅ Работает и локально, и в CI/CD
- ✅ Не нужно помнить о дополнительных шагах
- ✅ Чистый код, всё в одном месте
- ✅ Стандартная практика для Vite проектов

---

## 🎯 Почему это оптимально?

### 1. **Автоматизация**
- Плагин работает автоматически при каждой сборке
- Не нужно вручную добавлять шаги в CI/CD
- Работает одинаково локально и в production

### 2. **Надёжность**
- Всегда создаётся правильный `404.html` с актуальными путями к ресурсам
- Невозможно забыть об этом шаге

### 3. **Чистота кода**
- Вся логика в одном месте (плагин)
- Не засоряет workflow файлы
- Легко поддерживать

### 4. **Стандартная практика**
- Это рекомендуемый подход для Vite проектов
- Используется в большинстве современных SPA на GitHub Pages

## 🔄 Альтернативные решения (если нужны)

### Вариант A: Использовать Netlify/Vercel
```toml
# netlify.toml
[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200
```
**Плюсы:**
- Встроенная поддержка SPA routing
- Не нужен `404.html`

**Минусы:**
- Нужно менять хостинг (вы уже на GitHub Pages)
- Может быть платным для кастомных доменов

---

```json
// cloudflare.json
{
  "redirects": [
    { "from": "/*", "to": "/index.html", "status": 200 }
  ]
}
```
**Плюсы:**
- Бесплатно
- Встроенная поддержка SPA

**Минусы:**
- Нужно мигрировать с GitHub Pages

## 🔍 Как это работает

1. **При сборке (`pnpm build`):**
   - Vite собирает проект в `dist/`
   - Плагин `githubPages404()` срабатывает в хуке `closeBundle`
   - Копирует `dist/index.html` → `dist/404.html`

2. **При деплое на GitHub Pages:**
   - GitHub Pages ищет файл по пути (например, `/income`)
   - Не находит → отдаёт `404.html`
   - `404.html` загружает React приложение
   - React Router обрабатывает путь `/income` и показывает нужную страницу

3. **Результат:**
   - Все маршруты работают при обновлении страницы ✅
   - Прямые ссылки работают ✅
   - SEO-friendly URLs ✅
